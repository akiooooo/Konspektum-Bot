## Раздельные уведомления

`NOTIFY_CHAT_ID` задаёт группу заказов и переписки, `LOG_CHAT_ID` — группу
служебных логов уровня INFO и выше. Для супергрупп нужен полный ID с `-100`.
Бот должен иметь право отправлять сообщения в обе группы. Изменения `.env`
применяются после перезапуска; группа заказов также меняется в админке.
Ошибки доставки заказов направляются в группу заказов, остальные логи — в группу
логов. Очередь логов ограничена 500 сообщениями и хранится в памяти; при переполнении
новые записи остаются только в консоли. Токен в логах скрывается.

Магазин конспектов на машинке: Telegram-бот, гостевой сайт, личный кабинет и общая панель управления. Покупатель выбирает услуги, количество, срок и пожелания. Материалы, окончательная стоимость и оплата согласуются в чате заказа внутри бота.

## Самый простой запуск на компьютере

Нужны **Python 3.12+**, доступ к Telegram и интернет для первоначальной установки. Поддерживаются Windows, Linux и macOS с подходящим Python. Для установки из любой папки:

На Windows используйте обычный **CPython с python.org** (рекомендуется 3.13). Python из MSYS2/MinGW/Cygwin для автоматического запуска не поддерживается. При запуске из PyCharm уже активное окружение проекта используется повторно; скрипт не пересоздаёт его поверх работающего интерпретатора.

```sh
git clone https://github.com/akiooooo/Konspektum-Bot.git
cd Konspektum-Bot
python run.py
```

Скрипт создаст `.venv`, установит зафиксированные зависимости и, если настройки отсутствуют, создаст `.env`. Заполните файл и повторите `python run.py`. На Linux/macOS команда может называться `python3`.

Если PyCharm запускает `.venv/bin/python.exe` с базовым Python из `C:\msys64\...`, остановите запуск, закройте PyCharm и переименуйте `.venv` в `.venv-old`. Установите Python 3.13 для Windows с [официального сайта](https://www.python.org/downloads/windows/). В папке проекта выполните `py -3.13 run.py`. Затем в PyCharm → Python Interpreter выберите созданный `.venv\Scripts\python.exe`. Не переносите старое окружение в новое; `.env` и каталог данных оставьте на месте. Для Windows стандартная структура — `Scripts`, для Linux/macOS — `bin`.

Если установщик сообщает `Missing dependencies for SOCKS support`, он подхватил SOCKS-прокси без необходимого модуля. `run.py` распознаёт эту ошибку и один раз повторяет установку напрямую по HTTPS. Прямое подключение можно выбрать сразу: `py -3.13 run.py --direct` (или `python run.py --direct`). Это действует только на процесс установки зависимостей: глобальный прокси, настройки VPN и окружение работающего бота не меняются. Проверка TLS остаётся включённой. Прямое подключение требует доступа к PyPI; если сеть доступна исключительно через SOCKS, потребуется заранее установить поддержку SOCKS в окружение из доверенного локального пакета.

Обязательные настройки:

```dotenv
BOT_TOKEN=
ADMIN_IDS=
SHOP_USERNAME=
```

- `BOT_TOKEN` — токен вашего бота из **@BotFather**. Не публикуйте его.
- `ADMIN_IDS` — числовые Telegram ID владельцев через запятую. Свой ID можно узнать через `@userinfobot`; после запуска доступна команда `/id` в своём боте.
- `SHOP_USERNAME` — публичный username аккаунта магазина, справочный контакт владельца. Покупатель общается через чат заказа в боте. Без `@`.

Остальные настройки описаны в `.env.example`. Username самого бота приложение получает через Telegram автоматически; его не нужно угадывать или указывать на сайте вручную.

Локальный сайт: **http://127.0.0.1:8080**. Для локального доступа используйте `HOST=127.0.0.1`. Каждый администратор должен нажать **Start** в боте, чтобы получать сообщения. Управление в боте — `/admin`; на сайте — **Войти через Telegram**, затем **Управление**.

Без токена можно посмотреть внешний вид: `python run.py --preview`. Это отдельная локальная база, без подмены авторизации и реальных заказов. На страницах нет технических плашек и вымышленных отзывов. Для работы оформления нужен действующий бот.

## Установка на сервер с автоматическим HTTPS

Нужны Linux-сервер, Docker с Compose **2.24.4+**, домен с DNS-записью на сервер и доступные порты **80/443**. На Windows/macOS для контейнеров нужен Docker Desktop с Linux-контейнерами.

```sh
git clone https://github.com/akiooooo/Konspektum-Bot.git
cd Konspektum-Bot
cp .env.example .env
chmod 600 .env
```

Заполните `BOT_TOKEN`, `ADMIN_IDS`, `SHOP_USERNAME` и `SHOP_DOMAIN` — ваш домен **без** `https://`. Затем:

```sh
docker compose -f compose.yaml -f compose.server.yaml up -d --build
```

Caddy получает HTTPS-сертификат. Серверный Compose автоматически задаёт `WEBAPP_URL=https://ваш-домен`; порт приложения не публикуется наружу. Покупатель открывает сайт по домену; та же витрина доступна кнопкой в Telegram. На сервере должна работать **одна** копия приложения с одним токеном. Приложение использует long polling; настройки webhook не требуются. Существующий webhook оно не удаляет автоматически.

Для диагностики:

```sh
docker compose -f compose.yaml -f compose.server.yaml ps
docker compose -f compose.yaml -f compose.server.yaml logs --tail=100 shop
```

`GET /health` проверяет доступность приложения. Контейнер работает без root, с файловой системой только для чтения, отдельным томом данных и ограничением размера журналов. Если подсеть `172.30.77.0/24` уже используется на сервере, измените подсеть и оба адреса в `compose.server.yaml` вместе с `TRUSTED_PROXY_IPS`.

### Если обратный прокси уже есть

Запустите `docker compose up -d --build`. Приложение будет доступно только на `127.0.0.1:8080`. Настройте свой прокси на этот адрес. В `.env` укажите настоящий корневой `WEBAPP_URL=https://ваш-домен`, без пути и параметров. `TRUSTED_PROXY_IPS` должен содержать только фактические адреса вашего прокси, если нужно учитывать IP посетителей из `X-Forwarded-For`. Не доверяйте этому заголовку от произвольных клиентов.

## Оформление с сайта

1. Покупатель собирает корзину, выбирает срок и оставляет пожелания.
2. Сервер проверяет цены и создаёт временный выбор на один час. В ссылке находится случайный одноразовый код; текст заказа и личные данные туда не помещаются.
3. Сайт открывает Telegram-бота. Покупатель нажимает **Начать** — Telegram требует это действие для запуска бота.
4. Бот автоматически создаёт заказ, закрепляет его за Telegram ID покупателя и показывает номер, состав и кнопку чата заказа в боте. Повторное нажатие не создаёт копию.
5. Оплата, материалы и итоговые условия согласуются в чате заказа в этом боте.

При изменении цен сервер требует обновить расчёт. На сайте открытая корзина сохраняет ваши пожелания, чтобы можно было проверить новую цену и продолжить. Вход в личный кабинет для выбора услуг не обязателен.

## Вход на сайт и работа с заказами

**Войти через Telegram** показывает шестизначный код. В боте нужно сравнить код и нажать **Подтвердить вход**. Браузер обновится автоматически. Не подтверждайте вход, начатый другим человеком. Вход действует один час; кнопка **Выйти** отзывает сессию.

Покупатель видит только свои заказы. Администраторы из `ADMIN_IDS` получают раздел **Управление**: последние 100 заказов, поиск по клиенту, номеру и предмету, фильтр по статусу, услуги и настройки. Администраторские права не выдаются через браузер и не зависят от username.

При смене статуса из любой админки покупатель получает сообщение в боте. Повторное сохранение того же статуса не создаёт лишних уведомлений. Сетевые ошибки ставят уведомление в очередь. Если покупатель заблокировал бота, доставка невозможна, но статус и заказ сохраняются. При быстром изменении статуса старые ещё не отправленные уведомления заменяются актуальным. После сбоя в момент отправки возможно повторное уведомление: Telegram не предоставляет ключ идемпотентности для сообщений.

## Переписка через подключённый Telegram

В панели нажмите **Ответить в Telegram** у заказа. Видны сохранённые сообщения и состояние доставки. Ответ отправляется **от имени бота**, исключительно владельцу выбранного заказа. Повтор одного запроса не отправляет сообщение заново.

Покупатель отвечает кнопкой **Ответить по заказу**, **Обсудить заказ в боте** или обычным Telegram-ответом на сообщение магазина. Его текст появляется в той же переписке сайта; администраторам приходит уведомление. Поддерживается текст до 2000 символов, фотографии и документы до 20 МБ. Клиент и администратор могут отправить несколько сообщений подряд без повторного выбора заказа. Подпись к исходящему фото — до 900 символов. В панели сайта администратор может прикрепить JPEG, PNG или WebP до 8 МБ; фото можно посмотреть, документы скачать. Вложения выдаются только владельцу заказа и администраторам, токен бота в браузер не передаётся. Бот не читает личную переписку вашего личного аккаунта и не требует доступа к нему.

Если Telegram не подтвердил доставку, интерфейс честно показывает неопределённое состояние. Перед новой отправкой проверьте переписку: сообщение могло дойти. Автоматического повтора произвольных ответов нет, чтобы не дублировать их покупателю.

## Синхронизация Telegram и сайта

Каталог, настройки, заказы и сообщения хранятся в **одной SQLite-базе**. Изменения действуют сразу на сервере; открытые страницы каталога и панели обновляются каждые 10 секунд, пока вы не редактируете форму. Бот читает актуальные данные при каждом действии. На форме заказа цену дополнительно проверяет сервер.

Контакт магазина из админки имеет приоритет над первоначальным `SHOP_USERNAME`. Для `NOTIFY_CHAT_ID` приложение запоминает значение окружения: изменение `.env` применяется при следующем запуске; если `.env` не менялся, настройка из панели сохраняется. Кнопка «Чат из .env» принудительно загружает текущее значение окружения. Токен и список администраторов меняются в окружении с перезапуском. Удаление услуги — скрытие с возможностью возврата; старые заказы сохраняют собственные названия и цены.

## Обновление, резервная копия и восстановление

Обновление на сервере:

```sh
git pull --ff-only
docker compose -f compose.yaml -f compose.server.yaml up -d --build
```

Перед обновлением сделайте проверенную копию SQLite без остановки магазина:

```sh
docker compose exec shop python -m konspektum.maintenance
```

По умолчанию копии сохраняются в `/app/data/backups` внутри тома. Выгрузите их на отдельное хранилище: копия в том же томе не защищает от потери сервера. Локально: `python -m konspektum.maintenance` из установленного окружения или `.venv`.

Для восстановления остановите магазин, сохраните текущий каталог данных, положите проверенную копию на место `konspektum.sqlite3`, уберите старые файлы `-wal`/`-shm` из рабочего каталога и запустите приложение. У файла должен остаться владелец контейнера UID/GID `10001`. Не копируйте один SQLite-файл поверх работающего приложения и не используйте `docker compose down -v`, если нужны прежние данные.

## Проверки

```sh
python -m pip install -r requirements.lock
python -m unittest discover -s tests -v
node --check konspektum/static/shop.js
python -m pip check
python scripts/check_secrets.py
```

Проверяются обычный бот, перенос заказа с сайта, дубли, смена цены, авторизация, CSRF, разграничение заказов, цены и услуги, переписка, очередь статусов и резервная копия. Тесты используют временные базы и подменённый Telegram, не отправляют реальные сообщения. GitHub Actions запускает проверки на Windows/Linux с Python 3.12/3.13, сборку контейнера и аудит зависимостей.

Изолированный интерфейс панели с тестовыми данными: `python -m tests.serve_fixture`, адрес `http://127.0.0.1:8092`. Он не использует `.env` и рабочую базу; тестовая авторизация существует только в этом отдельном сервере. Файлы тестов не попадают в рабочий контейнер.

Проверка интерфейса: установите Playwright отдельно (`pip install playwright`,
`python -m playwright install chromium`), запустите тестовый сервер и выполните
`python scripts/check_ui.py`. Скрипт проверяет каталог, корзину и админку на desktop,
отсутствие горизонтальной прокрутки на ширине 390 px и ошибки JavaScript.
Снимки в `docs/screenshots` содержат только тестовые данные.

Архив исходников без рабочей базы и окружения: `python scripts/package_release.py`.
Проверка истории перед публикацией: `python scripts/audit_publication.py`.

## Безопасность и ограничения

Подробнее — [SECURITY.md](SECURITY.md). Встроенной оплаты нет. Защита включает проверку подписи Telegram, одноразовые ссылки, ограниченный срок сессий, HttpOnly cookies, CSRF, контроль владельца заказа, ограничения запросов, серверную проверку цен и экранирование текста. Токены, базы и `.env` исключены из Git и контейнерного контекста. Публикация проверяется отдельным сканером секретов.

Заказы и переписка сохраняются при перезапуске. Незавершённая корзина обычного бота хранится в памяти и сбрасывается; корзина сайта — в текущей вкладке браузера. Вложения хранятся в Telegram, в базе остаются их идентификаторы; сайт скачивает их только по запросу авторизованного владельца или администратора. Сервис рассчитан на один процесс и небольшой магазин; распределённый запуск нескольких копий требует отдельной архитектуры. Максимум 10 новых заказов на пользователя в час, 100 услуг и 5000 единиц на позицию (можно уменьшить в админке), сумма до 1 000 000 ₽.

Для публикации сайта нужны ваш сервер и домен. Репозиторий и локальная проверка сами по себе не создают публичный адрес.

Если Telegram сообщает о другой копии с тем же токеном, приложение останавливается с понятным сообщением. Не запускайте локальный бот одновременно с серверным: вход с сайта должен подтверждаться ботом, который использует ту же базу. После остановки лишней копии запустите нужную и начните вход с её сайта заново.

Попытки входа в разных вкладках независимы. Повторное открытие уже подтверждённой ссылки предлагает вернуться на сайт; повторная проверка завершённого входа не показывает ошибку. При кратковременном обрыве связи сайт повторяет проверку до окончания срока ссылки.

Изучены публичные страницы и документация; закрытые внутренние экраны этих ботов не копировались. Оформление Конспектума самостоятельное. Кнопки бота используют стандартное оформление Telegram без принудительных цветовых стилей.

## Выход и удаление

Кнопка выхода завершает все сессии этого Telegram-аккаунта на всех копиях сайта, а также отзывает старые данные входа Mini App и уже подтверждённые незавершённые попытки входа. Сервер закрывает доступ сразу; открытые видимые вкладки проверяют вход каждые 10 секунд и при возвращении в окно. Для нового входа Mini App переоткройте его из бота.

Администратор может удалить заказ в Telegram и на сайте. В Telegram требуется отдельная кнопка подтверждения, на сайте — ввод номера заказа. Удаление убирает заказ, сообщения, ссылки заказа и ожидающие уведомления из рабочей базы. Отправленные сообщения в Telegram, файлы у участников и старые резервные копии автоматически не удаляются.

После обновления кода на другом компьютере остановите старый процесс, выполните `git pull --ff-only`, запустите `python run.py` и обновите страницу сайта. Миграция базы выполняется автоматически; существующие заказы сохраняются. Не запускайте параллельно вторую копию с тем же токеном.

## Уведомления в закрытую группу

1. Добавьте бота в нужную группу и разрешите ему отправлять сообщения (и фото, если нужны вложения). Для обычной группы права администратора боту не обязательны; для канала нужны права публикации.
2. Администратор магазина из `ADMIN_IDS` отправляет в группе `/chatid` или `/chatid@имя_бота`. Бот покажет полный числовой ID этой группы. Не используйте ID участника или только цифры из ссылки `t.me/c/...`.
3. Сохраните ID в **Управление → Настройки → Чат уведомлений** или в `NOTIFY_CHAT_ID` с перезапуском. ID группы отрицательный; у супергруппы обычно начинается с `-100`.
4. Нажмите **Проверить уведомления** в настройках бота или сайта. На сайте кнопка сохраняет введённый ID перед проверкой. Если нужное значение уже есть в `.env`, можно нажать **Чат из .env**.
5. Проверка покажет успех или понятную причину Telegram. Если основной чат недоступен, уведомление о заказе/сообщении дублируется администраторам в бот. Каждый администратор должен ранее нажать Start.

При превращении группы в супергруппу Telegram меняет ID: приложение обрабатывает ответ миграции, сохраняет новый ID и повторяет отправку один раз. В уведомлениях группы есть ссылка на заказ в личном интерфейсе бота; управление по этой ссылке доступно только `ADMIN_IDS`. Участие в группе само по себе не даёт прав администратора магазина.
