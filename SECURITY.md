# Безопасность Конспектума

## Проверенные границы доступа

- Telegram Mini App: HMAC-SHA256 подпись `initData`, проверка времени (1 час), запрет повторяющихся параметров. `initDataUnsafe` не используется для доступа.
- Обычный сайт: подтверждение входа отдельной кнопкой в боте, код для сравнения с браузером, 5 минут на подтверждение. Код ссылки и секрет браузера различны. Сессия — случайный HttpOnly/SameSite=Strict cookie, срок 1 час; в БД хранится только хеш токена. В продакшене `WEBAPP_URL=https://...` включает Secure cookie и HSTS.
- Изменяющие запросы с cookie требуют CSRF-токен; все API-изменения требуют JSON и проверяют Origin, если он передан. CORS для сторонних сайтов не включён.
- Права администратора определяются только списком числовых Telegram ID в окружении. Каждая операция и каждый обработчик ввода проверяет доступ.
- Пользователь может читать только свои заказы и сообщения. Ответ панели всегда адресуется ID из заказа, а не произвольному получателю из формы.
- Временные заказы: 256-битный случайный код, в базе только его SHA-256, срок 1 час, атомарное однократное закрепление за Telegram ID. В ссылке нет текста заказа.

## Данные, цены и сообщения

- Цены и количество проверяются на сервере, деньги — целые копейки. При изменении цены нужно повторное подтверждение. Идемпотентность защищает заказ и исходящий ответ от двойного запроса.
- SQLite использует параметризованные запросы, транзакции и WAL. Созданный заказ сохраняет снимок услуг и цен.
- Пользовательский текст экранируется в HTML и Telegram. Установлены CSP, `nosniff`, запрет доступа к камере, микрофону и геопозиции; отдаются только разрешённые статические файлы.
- Тексты сообщений ограничены по длине; размер API-запроса — 32 КиБ. Есть лимиты на частоту, число заказов, временных выборов и запросов входа. Хранилище ограничителя имеет верхнюю границу числа ключей.
- IP из `X-Forwarded-For` учитывается только от явно доверенного прокси. В серверном Compose доверяется одному адресу Caddy.
- Смена статуса сохраняет событие в БД до попытки Telegram-доставки. Сетевые сбои повторяются; блокировка бота отмечается отдельно. Старые ожидающие статусы заменяются актуальным. Возможен повтор после аварии в момент отправки, поскольку Telegram не поддерживает ключ идемпотентности для `sendMessage`.
- Ответ администратора получает состояния «отправляется», «доставлено», «не доставлено», «доставка не подтверждена». Неопределённые ответы автоматически не пересылаются.

## Секреты и развёртывание

- `.env`, файлы базы, логи, резервные копии и артефакты не публикуются в Git. Скрипт `scripts/check_secrets.py` проверяет индекс Git и не печатает найденные значения.
- Образ Docker не содержит `.env` и тестового сервера. Пользователь контейнера — UID 10001, root отключён. Compose ограничивает права, делает корневую ФС только для чтения и хранит базу в отдельном томе.
- Серверный Compose публикует только HTTPS-шлюз; приложение недоступно напрямую. Нужны корректные DNS, доступные 80/443 и актуальные Docker/Caddy/ОС.
- Токен удаляется из строк стандартного журнала приложения. Не используйте подробные сторонние HTTP-журналы с секретами в URL и заголовках. Не публикуйте `.env` или исходный прикреплённый файл.
- Зависимости рабочего приложения зафиксированы в `requirements.lock`. Проверка `pip-audit` 10 ноября 2026 года не нашла известных уязвимостей в этом наборе. Это не гарантия отсутствия неизвестных проблем; аудит повторяется в CI.
- GitHub Actions закреплены на конкретных коммитах официальных actions. Права workflow ограничены чтением репозитория.

## Эксплуатационные ограничения

Нет встроенной оплаты, проверки перевода, автоматического удаления персональных данных, антивирусного анализа файлов и интеграции с личным Telegram-аккаунтом. Переписка панели относится к сообщениям через бота, а не к вашим личным чатам. Материалы передаются магазину в ЛС.

Хранятся Telegram ID, имя, username, состав и статус заказов, комментарии и текст переписки. Ограничьте доступ к серверу, используйте HTTPS, регулярно выносите проверенные резервные копии на отдельное хранилище. Срок хранения и обработка запросов на удаление — ответственность владельца магазина.

Отсутствие уведомления не означает потерю заказа: проверьте панель. Покупатель, заблокировавший бота, не сможет получать от него уведомления. Переписка и статусы сохраняются даже при ошибках Telegram.

Не запускайте одновременно несколько polling-процессов с одним токеном. Не меняйте файлы SQLite поверх запущенного приложения. Если токен скомпрометирован, отзовите его в BotFather, замените в окружении и перезапустите сервис; завершите существующие веб-сессии в базе.
